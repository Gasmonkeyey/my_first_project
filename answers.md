# Ответы на вопросы для самоконтроля

## 1. Три основные области работы с файлами в Git
- Рабочая папка (Working Directory) — текущие файлы проекта.
- Индекс (Staging Area) — промежуточная область, куда файлы попадают после git add.
- Репозиторий (Repository) — зафиксированные коммиты (папка .git).

Отличие: рабочая папка — «черновик», индекс — «подготовка к коммиту», репозиторий — «история версий».

## 2. Что происходит при выполнении команд
- git add — добавляет изменения в индекс (staging area).
- git commit — фиксирует содержимое индекса в репозиторий с сообщением.
- git push — отправляет локальные коммиты в удалённый репозиторий.

## 3. Почему важны информативные сообщения коммитов
Они помогают понять историю изменений: что, когда и зачем менялось. «update» или «исправление» ничего не говорят о сути правок, что затрудняет работу в команде и откат изменений.

## 4. Чем отличается git add имя_файла от git add .
- git add имя_файла — добавляет только конкретный файл.
- git add . — добавляет все изменения в текущей директории.

Первый вариант — когда нужно закоммитить часть изменений, второй — когда все изменения логически связаны.

## 5. Что показывает git status
Текущую ветку, изменённые файлы, файлы в индексе, неотслеживаемые файлы. На разных этапах вывод меняется: от «nothing to commit» до списка изменённых/новых файлов.

## 6. Для чего git remote add origin URL и что означает origin
Команда связывает локальный репозиторий с удалённым. origin — стандартный псевдоним удалённого репозитория, чтобы не писать полный URL каждый раз.

## 7. Зачем флаг -u в git push -u origin main
-u (--set-upstream) связывает локальную ветку с удалённой. После этого можно писать просто git push и git pull без указания ветки и remote.

## 8. Ветка по умолчанию
Исторически — master, сейчас GitHub по умолчанию использует main. Важно, потому что от имени ветки зависят команды push/pull и взаимодействие с удалённым репозиторием.

## 9. Как просмотреть историю коммитов
- git log — полная история
- git log --oneline — краткая (хэш + сообщение)
- git log --graph --oneline --all — с графом веток

Видно: хэш коммита, автора, дату, сообщение.

## 10. Что будет, если изменить файл без git add перед git commit
Изменения не попадут в коммит. Git закоммитит только то, что было в индексе. Файл останется в статусе modified.
